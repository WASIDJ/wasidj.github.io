<h2 id="1-背景与定义">1. 背景与定义</h2>
<h3 id="什么是fido">什么是FIDO？</h3>
<p><strong>FIDO</strong>（Fast Identity Online，快速身份在线）是由 <a href="https://fidoalliance.org/" rel="noopener noreferrer">FIDO Alliance</a> 于2012年成立的开放行业协会制定的一系列身份认证标准。其核心目标是<strong>减少全球对密码的依赖</strong>，提供更安全、更便捷的认证方式。</p>
<blockquote class="callout callout-info">
<p class="callout-title">FIDO Alliance</p>
<p>FIDO Alliance由250多家全球领先企业组成，包括Google、Apple、Microsoft、Amazon、Intel、ARM等科技巨头，以及Visa、Mastercard等金融支付公司。该联盟负责制定和维护FIDO相关技术规范。</p>
</blockquote>
<p>根据 <a href="https://www.verizon.com/business/resources/reports/dbir/" rel="noopener noreferrer">Verizon 2024数据泄露调查报告</a>，网络钓鱼攻击的发生率逐年增长，凭证泄露仍是首要安全威胁。FIDO协议从根本上解决了这些问题。</p>

<h2 id="2-核心概念解释">2. 核心概念解释</h2>
<h3 id="fido2技术架构">FIDO2技术架构</h3>
<p>FIDO2由两个核心技术组成：</p>
<ol>
<li><strong>WebAuthn</strong>（Web Authentication）：W3C标准的浏览器API，定义了网页应用如何与认证器交互</li>
<li><strong>CTAP</strong>（Client to Authenticator Protocol）：客户端与认证器之间的通信协议</li>
</ol>

<h3 id="passkeys通行密钥">Passkeys（通行密钥）</h3>
<p><strong>Passkeys</strong>是FIDO2的核心应用场景，它<strong>完全替代密码</strong>，而非作为第二因素。</p>
<blockquote class="callout callout-tip">
<p class="callout-title">Passkeys vs 密码</p>
<p>Passkeys是<strong>抗钓鱼</strong>的加密凭证，使用非对称密钥对（公钥/私钥）实现认证。私钥永远不离开用户设备，即使服务器数据库泄露，攻击者也无法获取可用于登录的凭证。</p>
</blockquote>

<h4 id="认证流程authentication">认证流程（Authentication）</h4>
<pre class="mermaid-source"><code class="language-mermaid">sequenceDiagram
    participant U as 👤 用户
    participant B as 🌐 浏览器
    participant R as 🖥️ 服务端

    U->>B: 点击"登录"
    B->>R: 请求认证挑战

    A->>B: 返回签名响应

<blockquote class="callout callout-warning">
<p class="callout-title">抗钓鱼原理</p>
<p>认证器在注册时会记录网站域名（RP ID）。认证时，浏览器必须提供匹配的域名，否则认证器拒绝签名。这意味着即使攻击者创建了完美的钓鱼页面，由于域名不匹配，认证也会失败。</p>
</blockquote>
<h2 id="3-技术深度分析">3. 技术深度分析</h2>
<h3 id="安全模型">安全模型</h3>
<p>FIDO的安全性基于以下核心原则：</p>
<ol>
<li><strong>非对称加密</strong>：每个凭证使用唯一的密钥对，私钥永不离开认证器</li>
<li><strong>挑战-响应机制</strong>：每次认证使用一次性挑战值，防止重放攻击</li>
<li><strong>域名绑定</strong>：凭证与特定域名关联，防止跨站攻击</li>
<li><strong>用户验证</strong>：需要本地验证（PIN/生物识别）才能使用私钥</li>
</ol>

<h3 id="ctap-22新特性">CTAP 2.2新特性</h3>
<p>2025年2月发布的 <a href="https://fidoalliance.org/specs/fido-v2.2-ps-20250228/fido-client-to-authenticator-protocol-v2.2-ps-20250228.html" rel="noopener noreferrer">CTAP 2.2</a> 规范引入了重要改进：</p>
<ul>
<li><strong>企业级认证</strong>（Enterprise Attestation）：允许企业部署的密钥提供更详细的设备信息</li>
<li><strong>备用UI</strong>：支持在没有显示屏的设备上配置认证器</li>
<li><strong>最小PIN长度策略</strong>：服务器可要求更长的PIN</li>
<li><strong>凭证管理改进</strong>：更好的凭证发现和管理能力</li>
</ul>

<ul>
<li><strong>信号API</strong>：允许网站报告被钓鱼的凭证使用</li>
<li><strong>远程桌面支持</strong>：改进远程环境下的认证体验</li>
<li><strong>多设备声明</strong>：更好地支持跨设备场景</li>
<li><strong>第三方认证器</strong>：改进的第三方认证器API</li>
</ul>

<li>最广泛的兼容性——几乎支持所有主流服务</li>
<li>多种形态（USB-A、USB-C、NFC、Lightning）</li>
<li>支持FIDO2、U2F、TOTP、HOTP、PIV、OpenPGP、YubiOTP</li>
<li>当前固件（5.7+）支持100个Passkey槽位</li>
<li>FIDO Level 2认证</li>
</ul>
<p><strong>劣势：</strong></p>
<ul>
<li>闭源固件——无法审计代码</li>
<li>不支持固件更新——发现漏洞需购买新设备</li>
<li>较高价格</li>
<li>美国公司（部分地区用户可能有管辖权顾虑）</li>
</ul>
<blockquote class="callout callout-warning">
<p class="callout-title">YubiKey安全事件</p>
<p>2024年，YubiKey 5系列被发现存在 <a href="https://www.yubico.com/support/security-advisories/ysa-2024-03/" rel="noopener noreferrer">安全漏洞</a>，由于固件不可更新，受影响用户只能购买新设备。这突显了开源固件和可更新能力的重要性。</p>
</blockquote>
<h4 id="nitrokey详解">Nitrokey详解</h4>
<p><a href="https://www.nitrokey.com/" rel="noopener noreferrer">Nitrokey</a> 是德国公司开发的开源硬件安全密钥，注重透明度和可审计性。</p>
<p><strong>优势：</strong></p>
<ul>
<li>完全开源固件——可审计安全性</li>
<li>支持固件更新——漏洞可修补</li>
<li>EAL 6+认证安全芯片（Nitrokey 3）</li>
<li>欧盟隐私管辖权</li>
<li>多种型号适应不同需求</li>
</ul>
<p><strong>劣势：</strong></p>
<ul>
<li>生态系统小于YubiKey</li>
<li>部分功能不如YubiKey成熟</li>
<li>Passkey容量不一（35-100个）</li>
</ul>
<h4 id="canokey详解">CanoKey详解</h4>
<p><a href="https://docs.canokeys.org/" rel="noopener noreferrer">CanoKey</a> 是清华大学团队开发的开源硬件安全密钥项目。</p>
<p><strong>优势：</strong></p>
<ul>
<li>完全开源</li>
<li>价格亲民</li>
<li>支持FIDO2、TOTP、OpenPGP</li>
<li>国内团队，本地支持</li>
</ul>
<p><strong>劣势：</strong></p>
<ul>
<li>非安全芯片版本存在物理访问风险</li>
<li>安全版本（Pigeon/Canary）价格较高</li>
</ul>

<h3 id="刷写固件">刷写固件</h3>
<h4 id="步骤1下载固件">步骤1：下载固件</h4>
<p>访问 <a href="https://github.com/polhenarejos/pico-fido/releases" rel="noopener noreferrer">Pico Keys固件发布页</a>，下载对应板子的<code>.uf2</code>文件。</p>
<p>对于Waveshare RP2350-One，下载<code>Raspberry Pico 2</code>版本的固件（完全兼容）。</p>
<h4 id="步骤2进入bootloader模式">步骤2：进入Bootloader模式</h4>
<ol>
<li>按住板子上的<strong>BOOTSEL</strong>按钮</li>
<li>将USB插入电脑</li>
<li>松开按钮</li>
<li>电脑会识别为一个USB存储设备</li>
</ol>
<h4 id="步骤3刷写固件">步骤3：刷写固件</h4>
<p>直接将下载的<code>.uf2</code>文件拖入该USB设备即可，设备会自动重启并完成刷写。</p>
<blockquote class="callout callout-tip">
<p class="callout-title">零门槛刷写</p>
<p>RP2040/RP2350的刷写过程极其简单，不需要任何驱动或特殊工具，就像复制文件一样。</p>
</blockquote>
<h4 id="步骤4启用安全特性强烈推荐">步骤4：启用安全特性（强烈推荐）</h4>
<p>刷写完成后，通过 <a href="https://www.picokeys.com/pico-commissioner/" rel="noopener noreferrer">Pico Commissioner在线工具</a> 启用安全特性：</p>
<ol>
<li>连接设备到浏览器</li>
<li>选择<strong>Secure Boot</strong>和<strong>Secure Lock</strong></li>
<li>应用配置</li>
</ol>
<blockquote class="callout callout-warning">
<p class="callout-title">Secure Boot影响</p>
<p>启用Secure Boot后，设备只能运行官方签名的Pico Keys固件。这提高了安全性，但限制了自定义能力。如需同时兼顾DIY灵活性和安全性，可参考 <a href="https://github.com/polhenarejos/pico-fido/issues/106" rel="noopener noreferrer">自签名指南</a>。</p>
</blockquote>

<h2 id="6-专业总结与应用建议">6. 专业总结与应用建议</h2>
<h3 id="安全实践最佳实践">安全实践最佳实践</h3>
<ol>
<li><strong>购买/制作至少两个密钥</strong>：一个日常使用，一个安全备份</li>
<li><strong>优先保护关键账户</strong>：邮箱 > 密码管理器 > 金融账户 > 云存储</li>
<li><strong>保存恢复代码</strong>：离线安全存储，作为最后的恢复手段</li>
<li><strong>使用强PIN</strong>：至少6位数字，避免简单序列</li>
<li><strong>启用Passkeys</strong>：在支持的服务上使用Passkeys完全替代密码</li>
